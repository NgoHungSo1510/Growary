# V2.6.2 Quiz & Season Pass Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Populate idempotent, rich, schema-validated data for Quiz Game (8 topics, 160+ questions, multi-status events, leaderboard attempts) and Sổ Sứ Mệnh / Season Pass (curated 80-tier rewards mapped to real DB MysteryBoxes, 4 seasonal MysteryBoxes, multi-season Avatar Frames, and 4 QA test personas).

**Architecture:** Modular data files under `backend/src/seeds/data/` (strictly `<= 450` lines/file), reusable typed seed functions under `backend/src/seeds/` orchestrated by a unified `backend/src/seeds/index.ts` CLI (`npm run seed`), plus clean updates to `shared/types/seasonPass.ts`, `seasonPassConfig.ts`, and `mobile/src/utils/seasonPassHelpers.ts` while respecting `ARCHITECTURE_RULES.md`.

**Tech Stack:** TypeScript (strict, zero `any`), Mongoose 8, Zod, Jest, React Native / Expo (`mobile`), React (`admin`).

**Spec:** [v2.6.2-quiz-and-seasonpass-data.md](file:///d:/Downloads/SE%20Project/Growary/plan%20update/v2/v2.6.2-quiz-and-seasonpass-data.md)

## Global Constraints

- **ARCHITECTURE_RULES.md §0.1:** Model `<= 250` lines, Service/Data module `<= 500` lines (target `<= 450` lines per quiz data file).
- **ARCHITECTURE_RULES.md §0.2:** Zero `any` in any new or refactored TypeScript seed/service file.
- **ARCHITECTURE_RULES.md §1.2:** No `deleteMany()` on production/user collections inside idempotent seeds; always upsert by natural unique key (`name`, `question`, `type`, `itemType`, `seasonCode`).
- **ARCHITECTURE_RULES.md §4.1:** Update `shared/types/` first and mirror to `backend/src/shared/` before referencing new frame metadata or reward fields.
- **V2.6 Economic Guardrails:** Total Coins across 80 Free+Elite Season Pass tiers `<= 2,500`; Vault cap `= 2,000`; Prestige Overcap max `10` chests; MysteryBox reward probabilities per box sum to `100`.
- **Quiz Validator Guardrails:** Every question has `question` (`5–300` chars), exactly `4` unique non-empty options (`1–200` chars each), `correctIndex` in `0..3` (~25% each), and `difficulty` in `easy | medium | hard`.

## Review Focus

1. **Exact `SpecialItem.type` lookup vs `.includes()` collision:** Ensure MysteryBox seeds resolve `discount_5k` vs `ship_5k` and `discount_10k` vs `ship_10k` by exact `type` key, never `.includes('5k')`.
2. **Idempotency across repeated `npm run seed` runs:** Running the full seed twice must yield `0` duplicate topics, questions, boxes, special items, or seasons.
3. **Single Active `QuizEvent` invariant:** Because `quizService.getActiveQuizEvent()` calls `QuizEvent.findOne({ status: 'active' })`, seeded demo events must keep exactly 1 `active` event and place extra configs in `upcoming` / `completed`.
4. **Startup seed non-destructive guarantee:** `ensureQuizSampleSeed()` and Season Pass tier binding must not overwrite custom edits made manually by Admin in MongoDB.
5. **Dual-repo sync:** Keep `shared/types/seasonPass.ts` and `backend/src/shared/seasonPass.ts` identical if extended.
