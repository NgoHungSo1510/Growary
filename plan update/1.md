## 🎮 PHẦN 1: THIẾT KẾ GAMEPLAY MỚI

### 1.1 Cơ chế "Điểm Công" (Attack Points)

```
TRƯỚC (V1):
  Hoàn thành task → XP tự trừ HP boss → User không cần vào trang Boss

SAU (V2):
  Hoàn thành task → Tích "Điểm Công" vào BossRecord.attackPoints
                   → Coins vẫn tích vào rương (giữ nguyên)
  
  User vào trang Boss → Thấy ⚡ X Điểm Công đang chờ
                       → Nhấn "⚔️ TẤN CÔNG!"
                       → Mini-game 10s xuất hiện (random 1 trong 3 kiểu)
                       → Kết quả:
                          ✅ Hoàn thành → damage = attackPoints × 2 (Critical!)
                          ⏱️ Bỏ qua     → damage = attackPoints × 1 (Normal)
                       → HP boss giảm + animation đánh
                       → attackPoints reset = 0
```

**Quy tắc:**
- Không giới hạn số lần tấn công/ngày — tấn công bất cứ khi nào có Điểm Công
- Nút "Tấn Công" chỉ hiện khi `attackPoints > 0`
- Nếu `attackPoints = 0`, hiện thông báo: *"Hoàn thành nhiệm vụ để tích Điểm Công!"*
- Streak break → boss vẫn hồi máu `BOSS_HEAL_AMOUNT = 50` (giữ nguyên V1)

### 1.2 Mini-Game tấn công (Random 1 trong 3 kiểu)

| # | Kiểu | Tên | Mô tả | Điều kiện Critical |
|---|------|-----|--------|-------------------|
| 🔴 | **Tap Speed** | "Mưa Kiếm" | Nhấn liên tục trong 5s | Đạt ≥20 tap |
| 🟡 | **Quick Quiz** | "Nhận Diện Yếu Điểm" | 1 câu trắc nghiệm từ pool admin tạo, 10s | Trả lời đúng |
| 🔵 | **Reflex Hit** | "Chém Chính Xác" | 3 vùng target xuất hiện ngẫu nhiên | Chạm đúng 3/3 |

**Logic chọn mini-game:**
- Nếu boss có câu hỏi quiz (`miniGameQuestions.length > 0`) → random 1/3 kiểu
- Nếu boss KHÔNG có câu hỏi quiz → random giữa "Tap Speed" và "Reflex Hit"

### 1.3 Mở khóa câu chuyện nhân vật

```
Boss bị tiêu diệt (HP = 0)
  → Tất cả user có đóng góp (totalDamageDealt > 0)
    → hasUnlockedStory = true
    → Lần đầu vào Boss page → Popup modal: Ảnh nhân vật + Lore text
    → Boss được thêm vào Bộ Sưu Tập cá nhân

Edge case: User có Điểm Công dư nhưng boss chết bởi người khác
  → Điểm Công dư biến mất
  → Chỉ cần totalDamageDealt > 0 là đủ nhận thưởng + unlock story
```

### 1.4 Bộ sưu tập boss theo tháng

```
Admin tạo "BossCollection" (VD: "Bộ Tháng 9 — Mùa Thu 🍂")
  → Gom N boss vào bộ (admin quyết N)
  → Config bonusTickets = số vé quà thưởng
  
User sưu tập = tiêu diệt boss + có đóng góp
  → Khi đủ N boss trong bộ → hiện nút "Nhận thưởng"
  → User nhấn → nhận bonusTickets vé quà
```

**TRƯỚC (V1)** — EXP tự trừ HP:
```typescript
activeBoss.currentHp = Math.max(0, activeBoss.currentHp - finalXpReward);

userRecord.pendingDamageAnimation += finalXpReward;
```

**SAU (V2)** — Tích Điểm Công:
```typescript
// Không trừ HP — tích Điểm Công
userRecord.attackPoints += finalXpReward;
userRecord.accumulatedCoins += Math.floor(finalCoinReward / 2);  // Giữ nguyên
```

### 3.2 [NEW] Attack Boss API
> `POST /events/boss/attack`

```
Body: { miniGameType: 'tap' | 'quiz' | 'reflex', miniGameResult: 'critical' | 'normal' }
Logic:
  1. Lấy userRecord.attackPoints
  2. critical → damage = attackPoints × 2
  3. normal → damage = attackPoints × 1
  4. Trừ activeBoss.currentHp -= damage
  5. userRecord.totalDamageDealt += damage
  6. userRecord.attackPoints = 0
  7. Boss HP ≤ 0 → trigger rewards + unlock story
```

### 3.3 [NEW] Mini-game Quiz API
> `GET /events/boss/quiz`

Trả về 1 câu hỏi random từ `boss.miniGameQuestions[]`

## 🎮 PHẦN 1: THIẾT KẾ GAMEPLAY & UI MỚI

### 1.1 Cơ chế Đập Khóa (Tấn Công)

- Hoàn thành task → Tích **"Điểm Công"** vào ví và **Coins bonus** vào rương (giống V2.0).
- Khi đánh, user **không bắt buộc dùng hết điểm**, mà chọn:
  - `[25%]` `[50%]` `[75%]` `[ALL-IN 100%]`
- **Random Mini-game 10s** xuất hiện (Tap Speed, Quick Quiz, Reflex Hit). Thắng = Damage × 2 (Critical), Bỏ qua = × 1 (Normal).
- **Cơ chế Refund (Hoàn trả dư sát thương):**
  - Nếu boss (ổ khóa) còn 150 HP. User xả 100 Điểm Công + Critical (×2) = 200 Damage.
  - Sát thương thừa = 50.
  - Hệ thống tự động chia lại cho hệ số (50 / 2 = 25 Điểm Công) và **trả lại 25 Điểm Công** vào ví cho user.

### 1.2 Trạng thái UI của Nhân vật

1. **Chưa mở khóa (Đang diễn ra):**
   - Ảnh nhân vật bị **CSS Blur (làm mờ 15px)** + Icon 🔒 cực to ở giữa.
   - Text đỏ: *"Nhân vật sự kiện giới hạn — Chỉ xuất hiện 1 lần!"*
   - Thanh HP khóa (ví dụ: 8,420 / 10,000).

2. **Đã mở khóa (Nhưng chưa sang nhân vật mới):**
   - Ảnh nhân vật **hiện rõ 100%**, mất ổ khóa.
   - Không có form tấn công nữa.
   - User nhấn vào ảnh → Popup **thông tin / truyện nhân vật**.

### 1.3 Hệ thống Bộ Sưu Tập (Collections) & Penalty

- **Hiển thị Collections:**
  - Nền layout xám. Icon ảnh đại diện bộ + **Tiến độ (VD: 60%)**.
  - Nếu sưu tập ĐỦ (100%) → Đổi sang **Viền Vàng phát sáng**.
  - Nhấn vào bộ → Hiện grid các nhân vật (dạng ô vuông). Nhấn vào nhân vật đã mở sẽ đọc được cốt truyện.
  - Nếu đủ 100% nhân vật → Hiện nút **"Đọc Truyện Bộ Sưu Tập"** (Truyện dài tổng kết) + **"Nhận thưởng bộ"** (Admin config).
- **Penalty kết thúc bộ:**
  - Khi một Bộ sưu tập kết thúc (Nhân vật cuối cùng của bộ hết thời gian).
  - Điểm Công của tất cả user sẽ bị **chia đôi (Mất 50%)**.
  - Lý do: Ép user phải tiêu thụ Điểm Công để cày nốt nhân vật trong bộ, không được "ngâm" điểm sang bộ khác.

### 1.4 Bảng Xếp Hạng & Phần Thưởng (Leaderboard)

Khi 1 nhân vật bị mở khóa (HP = 0) hoặc hết giờ, chia thưởng theo **Ranking đóng góp Damage**:
- **Top 1:** Nhận 100% (Thưởng gốc nhân vật: Coins, XP, Vé).
- **Top 2:** Nhận 75% thưởng gốc.
- **Top 3:** Nhận 50% thưởng gốc.
- **Top 4 trở đi:** Nhận 25% thưởng gốc.
- **RIÊNG Bonus Coins (Rương cá nhân):** Nhận 100% quỹ cá nhân của mình, không bị giảm trừ theo Top.

## 🗄️ PHẦN 2: THAY ĐỔI DATABASE & API

### 2.1 Models (`BossEvent` và `BossRecord` giữ nguyên tên để không bể code cũ)

**BossEvent (Đại diện cho Nhân vật bị khóa)**:
- Thêm: `avatarImageUrl`, `loreTitle`, `loreContent` (Truyện nhân vật).
- Thêm: `collectionId` (ObjectId), `miniGameQuestions` (Array).
- Thêm: `isLimited` (Boolean, default true).

**BossCollection (Đại diện cho 1 Bộ Nhân vật)**:
- Thêm: `title`, `coverImageUrl`, `completionStory` (Truyện tổng kết bộ), `bonusTickets`, `isActive`.

**BossRecord (Đại diện cho Session User đánh Nhân vật)**:
- Thêm: `attackPoints` (Điểm công), `hasUnlockedStory`.

### 2.2 API: Tấn công (Attack) tính Refund & Chọn %

```typescript
// POST /events/boss/attack
// Body: { miniGameType, miniGameResult, usePercentage: 0.25 | 0.5 | 0.75 | 1.0 }

const pointsToUse = Math.floor(userRecord.attackPoints * usePercentage);
const multiplier = miniGameResult === 'critical' ? 2 : 1;
const potentialDamage = pointsToUse * multiplier;

let actualDamage = potentialDamage;
let refundPoints = 0;

if (potentialDamage > activeBoss.currentHp) {
    actualDamage = activeBoss.currentHp;
    const overkillDamage = potentialDamage - actualDamage;
    refundPoints = Math.floor(overkillDamage / multiplier); // Trả lại điểm chưa xài
}

// Update Boss HP & User Record
activeBoss.currentHp -= actualDamage;
userRecord.attackPoints = (userRecord.attackPoints - pointsToUse) + refundPoints;
userRecord.totalDamageDealt += actualDamage;
```

### 2.3 API: Distribute Rewards & Leaderboard (Cron/Trigger)

Trong `services/bossService.ts` (`distributeBossRewards`):
1. Lấy tất cả `BossRecord` của boss đó, **sort theo `totalDamageDealt` DESC**.
2. Phân hạng Top 1, Top 2, Top 3, Top 4+.
3. Cấp phát thưởng:
   - `coinsReward = boss.baseRewardCoins * (1 | 0.75 | 0.5 | 0.25)`
   - `xpReward = boss.baseRewardXp * (1 | 0.75 | 0.5 | 0.25)`
   - Cộng thêm `record.accumulatedCoins` (Bonus từ quest, luôn 100%).
4. Set `hasUnlockedStory = true` cho tất cả user có tham gia đánh (Dù top mấy cũng đc đọc truyện nhân vật).

### 2.4 API: Halve Attack Points (Trừ 50% điểm)

Khi `BossCollection` kết thúc, tạo logic quét qua User Profiles hoặc BossRecords mới nhất của User, giảm `attackPoints = Math.floor(attackPoints / 2)`.
