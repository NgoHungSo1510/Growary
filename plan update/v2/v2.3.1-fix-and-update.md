# Báo cáo Code Review (Bản vá v2.3.1)

Sau khi rà soát lại toàn bộ các thay đổi vừa thực hiện, dưới đây là một số vấn đề rủi ro/chưa triệt để (edge cases) và các phần cần cải thiện thêm mà bạn có thể giao cho người khác (hoặc xử lý ở phase sau):

### 1. Vấn đề Rollback Giao dịch Mua hàng chưa dùng Database Transaction
* **File liên quan**: `backend/src/routes/rewards.ts` (API `POST /:rewardId/purchase`)
* **Mô tả lỗi tiềm ẩn**: Mặc dù tôi đã thêm logic rollback thủ công (hoàn trả số lượng Coupon và Stock) vào những chỗ dễ lỗi như "không đủ xu", nhưng nếu hệ thống bắn ra lỗi (`throw exception`) ở các bước sau (ví dụ: tạo Voucher thất bại do database sập, hoặc lỗi khi tính hạng VIP) thì hệ thống sẽ nhảy thẳng vào block `catch (error)`.
* **Hậu quả**: Block `catch` này chưa rollback lại số lượng Xu, Stock và Coupon đã bị trừ ở trên, dẫn đến việc người dùng bị mất Xu/Coupon oan.
* **Cách khắc phục**: Cần refactor lại API purchase sử dụng MongoDB Transaction:
  ```javascript
  const session = await mongoose.startSession();
  session.startTransaction();
  try {
     // ... logic trừ xu, coupon, tạo voucher, dùng { session } trong các câu query ...
     await session.commitTransaction();
  } catch (err) {
     await session.abortTransaction();
  } finally {
     session.endSession();
  }
  ```

### 2. Thiếu field `isFeatured` trong whitelist khi Cập nhật Quà (Admin)
* **File liên quan**: `backend/src/controllers/rewardController.ts` (Hàm `updateReward`)
* **Mô tả lỗi tiềm ẩn**: Hàm update API đang bóc tách (`whitelist`) các biến từ `req.body` để bảo mật (tránh Mass Assignment). Tuy nhiên, code hiện tại thiếu trường `isFeatured`.
* **Hậu quả**: Nếu admin tick chọn một món quà thành "Nổi bật" ở Admin UI, API cập nhật sẽ thành công nhưng database không thay đổi trạng thái `isFeatured`.
* **Cách khắc phục**: Bổ sung `isFeatured` vào danh sách extract biến: 
  ```javascript
  const { title, description, pointCost, imageUrl, stock, isActive, shippingFee, isFeatured } = req.body;
  ```

### 3. Điều hướng tới Bộ Sưu Tập ở Profile chưa tự động cuộn (Auto-scroll)
* **File liên quan**: `mobile/src/screens/ProfileScreen.tsx`
* **Mô tả**: Khi người dùng nhấn nút "Bộ sưu tập" ở màn hình đánh Boss (`BossEventScreen`), hệ thống sẽ chuyển trang qua Profile và highlight (tô viền đậm) bộ sưu tập tương ứng. Tuy nhiên, nó chưa tự động kéo màn hình (scroll) xuống đúng vị trí của bộ sưu tập đó.
* **Cách khắc phục**: Gắn `onLayout` cho các thẻ bộ sưu tập để lưu tọa độ Y, sau đó gọi `scrollViewRef.current?.scrollTo({ y: collectionY })` khi nhận được param `scrollToCollection` từ navigation route.
