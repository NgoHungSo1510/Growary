## 🎯 Mục Tiêu & Kiến Trúc Tổng Quan (Backend + Mobile + Web Admin + Shared)

Giải quyết đồng bộ bài toán vận hành trên **Server Render Free (ngủ đông sau 15 phút không có request)** trên cả **3 nền tảng (Backend, Mobile App, Web Admin)**:

1. **Ghi nhớ User & Phiên trượt 48h (trên cả Mobile App & Web Admin):**
   - Mở App hoặc Web Admin vào thẳng màn hình làm việc nếu lần hoạt động cuối `<= 48h`, tự động gia hạn thêm 48h mỗi lần thao tác.
   - Chỉ bắt nhập lại mật khẩu khi **không mở quá 48h** hoặc khi server trả mã xác thực rõ ràng `401 TOKEN_INVALID` / `SESSION_IDLE_EXPIRED` (tách biệt hoàn toàn với lỗi `503 SERVER_WAKING` hay `502/504` khi Render/MongoDB đang thức dậy).
   - Luôn ghi nhớ và điền sẵn Email đã đăng nhập gần nhất trên cả Mobile (`LoginScreen.tsx`) lẫn Web Admin (`Login.tsx`).
2. **Thông báo qua Account & Tự động duyệt sau 6h (Task & Shop Voucher):**
   - Khi user tạo nhiệm vụ tự chọn (`isCustomTask`) hoặc yêu cầu dùng voucher (`pending_use`), hệ thống gửi ngay `Notification` (`type: 'approval'`) vào **tài khoản của toàn bộ Admin** (hiển thị trên Chuông Thông Báo của Web Admin `TopBar` và hộp thư Mobile).
   - Nếu sau **6 giờ** chưa xử lý, hệ thống **tự động duyệt** qua cơ chế kép (**Cron 15 phút + Lazy Sweep ngay khi mở App / mở Web Admin**) và gắn cờ `autoApproved = true`, `adminReviewStatus = 'pending_review'` để đưa vào tab **"🤖 Tự duyệt — Chờ xem lại"** trên Web Admin.
3. **Thiết kế hoàn chỉnh Web Admin (Chuông thông báo Account, Đếm ngược 6h, Tab Hậu kiểm, Trung tâm Thông báo 2 phân khu):**
   - Bổ sung **Chuông Thông Báo Account Admin (`AdminNotificationBell.tsx`)** + trạng thái kết nối Server trên `TopBar.tsx`.
   - Hiển thị đếm ngược `⏳ Tự duyệt sau Xh Yp` ngay trên bảng chờ duyệt của `QuestManagement.tsx` và `VoucherRedeemTab.tsx`.
   - Thêm tab **"🤖 Tự duyệt — Chờ xem lại"** kèm thanh cấu hình ngưỡng tự duyệt (`AutoApproveConfigBar.tsx`) tại `QuestManagement.tsx` và `ShopRedemption.tsx`, cũng như thẻ cảnh báo nhanh trên `Dashboard.tsx`.
   - Thiết kế lại hoàn toàn `NotificationManagement.tsx` trên Web Admin thành 2 phân khu rõ ràng: **(1) Bảng 9 Trigger Hệ Thống Tự Động (Account Inbox)** và **(2) Quy Tắc Hẹn Giờ Offline Alarm Trên Điện Thoại**, giải thích minh bạch mỗi thông báo **hoạt động khi nào, gửi cho ai, và chạy ở đâu khi server ngủ**.
4. **Chẩn đoán & Sửa lỗi Thông báo Mobile + Chế độ Offline Outbox + Widget Android:**
   - Sửa lỗi thiếu Android Notification Channel (`Importance.MAX`) & race condition xin quyền; tải `NotificationConfig` về lưu cache làm **Offline Alarm** trên điện thoại; thêm Modal **Kiểm tra & Gửi thử thông báo sau 5s** trong `ProfileScreen`.
   - Lưu thao tác hoàn thành nhiệm vụ, viết nhật ký, tạo custom task vào hàng đợi `offlineQueue` trên máy kèm `idempotencyKey` (UUID) để tự đẩy lên khi server thức; cung cấp dữ liệu snapshot cho **Android Home Screen Widget**.

   ```typescript
   DailyPlan.findOneAndUpdate(
       { _id: planId, tasks: { $elemMatch: { _id: taskId, adminApprovalStatus: 'pending' } } },
       { $set: { 'tasks.$.adminApprovalStatus': 'approved', 'tasks.$.autoApproved': isAuto /* ... */ } },
       { new: true }
   );
   Voucher.findOneAndUpdate({ code, status: 'pending_use' }, { $set: { status: 'used' /* ... */ } }, { new: true });
   ```
   Nếu kết quả trả về `null` nghĩa là luồng khác vừa duyệt xong → bỏ qua, tuyệt đối không cộng điểm/xu hoặc tạo `TaskTemplate` lần 2. Cộng thưởng dùng `User.findByIdAndUpdate(userId, { $inc: ... })`, sau đó gọi `processLevelUp` như logic hiện tại.
2. **Bảo vệ Phiên trên cả Mobile lẫn Web Admin khi Server Render đang thức dậy (`Cold Start 502/503/504/Timeout`):** Trong `backend/src/middleware/auth.ts`, nếu `jwt.verify` ném `JsonWebTokenError` hoặc `TokenExpiredError` thì trả `401 { error: 'Invalid token', code: 'TOKEN_INVALID' }`. Nhưng nếu `User.findById` ném lỗi kết nối MongoDB, bắt buộc trả `503 { error: 'Database waking up', code: 'SERVER_WAKING' }`. Phía Mobile (`api.ts`) và Web Admin (`client.ts`) **chỉ xóa token khi nhận đúng `status === 401` và `code === 'TOKEN_INVALID' | 'SESSION_IDLE_EXPIRED'`**.
3. **Kiểm tra 48h không hoạt động ngay trên Client (`Offline-first 48h Sliding Window`):** Khi mở Mobile App hoặc Web Admin, trước khi gọi mạng, kiểm tra `lastActiveAt` (`AsyncStorage` trên Mobile, `localStorage` trên Web Admin). Nếu `<= 48h`, cho vào thẳng giao diện làm việc. **"Hoạt động" chỉ tính tương tác thật của người dùng** (*R7*): Mobile = app chuyển sang foreground; Web Admin = `click`/`keydown`/tab chuyển sang visible. **Polling nền (Sidebar 30s, Chuông 30s) KHÔNG được gia hạn phiên.**
